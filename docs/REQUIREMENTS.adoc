=== FEATURE: Capture Epics, Features, User Stories from Meetings
[cols="1,3a"]
|===
|*ID*          |FEAT-001
|*Title*       |Extract backlog items in real time from meeting transcripts
|*Description* |During a live Teams meeting, Pennie listens to discussion and generates Azure DevOps entries in the T-Minus-15 hierarchy (Epic > Feature > User Story). Items include required metadata and links.
|*Notes*       |Epics do not have acceptance criteria. Features include a `.Description`. User Stories use “As a … I want … so that …” and include `.Description` plus Gherkin acceptance criteria.
|*User Stories*|
* *As a product owner, I want to capture high-level goals as epics so that they can be tracked across features.*
**Acceptance Criteria**::
+
----
SCENARIO: Capturing a goal during project kickoff
GIVEN a Teams meeting is in progress
WHEN a participant states a high-level goal
THEN Pennie creates a new Epic in DevOps with title and description
AND the Epic includes lean business case fields (Who/Why/Scope/Outcome/Value/Impact/Investment)
----

* *As a business analyst, I want to generate user stories from spoken discussion so that I can refine them later.*
**Acceptance Criteria**::
+
----
SCENARIO: Detailing requirements mid-meeting
GIVEN participants describe steps in a workflow
WHEN Pennie identifies discrete user needs
THEN Pennie creates corresponding User Stories with description
AND adds Given/When/Then acceptance criteria
----

=== FEATURE: Ask Clarifying Questions in Chat
[cols="1,3a"]
|===
|*ID*          |FEAT-002
|*Title*       |Ask structured questions in Teams chat when data is missing
|*Description* |When information is ambiguous or incomplete, Pennie posts a concise question in Teams chat and logs a DevOps work item of type `Question`, linked to the relevant parent item.
|*Notes*       |Questions remain open until answered; answers are appended and the item is resolved.
|*User Stories*|
* *As a virtual business analyst, I want to prompt users for missing context so that backlog items are complete and actionable.*
**Acceptance Criteria**::
+
----
SCENARIO: A vague requirement is discussed
GIVEN a participant says "it needs to be faster"
WHEN Pennie detects ambiguity (missing KPI or baseline)
THEN Pennie posts a clarifying question in Teams chat
AND creates a linked `Question` work item capturing the question text
----
|===


=== FEATURE: Post Real-Time Change Log to Teams Chat
[cols="1,3a"]
|===
|*ID*          |FEAT-003
|*Title*       |Announce backlog changes with links in chat
|*Description* |Every time Pennie creates or updates a DevOps work item, she posts a short message in chat with a link and summary of the change for transparent collaboration.
|*User Stories*|
* *As a meeting participant, I want to see links to items Pennie creates or edits so that I can review and correct in real time.*
**Acceptance Criteria**::
+
----
SCENARIO: Change log visibility
GIVEN Pennie creates or updates a work item
WHEN the action completes
THEN a chat message is posted containing action, title, and link
AND the message includes a one-sentence summary of what changed
----
|===


=== FEATURE: Revise and Improve Existing Backlog Items
[cols="1,3a"]
|===
|*ID*          |FEAT-004
|*Title*       |Pennie improves and restructures backlog items
|*Description* |Pennie can review existing items to suggest clearer titles, add missing descriptions or acceptance criteria, reclassify items, and add linked questions where detail is insufficient.
|*User Stories*|
* *As a delivery lead, I want Pennie to suggest improvements to existing user stories so that backlog quality improves over time.*
**Acceptance Criteria**::
+
----
SCENARIO: A poorly written user story exists in DevOps
GIVEN a story lacks acceptance criteria and has an unclear title
WHEN Pennie reviews the story during grooming
THEN Pennie proposes improved title and adds suggested acceptance criteria
AND posts a chat summary with a link to the updated item
----
|===


=== FEATURE: Azure DevOps CRUD & Hierarchy Linking
[cols="1,3a"]
|===
|*ID*          |FEAT-005
|*Title*       |Create, read, update, and link DevOps work items with correct hierarchy
|*Description* |Pennie performs CRUD operations for Epics, Features, User Stories, and Questions; maintains parent/child links; preserves IDs and URLs for posting back to chat.
|*User Stories*|
* *As a product owner, I want new requirements linked correctly so that the backlog retains accurate hierarchy and traceability.*
**Acceptance Criteria**::
+
----
SCENARIO: Creating a new user story under a feature
GIVEN an existing Feature is referenced
WHEN Pennie creates a new User Story
THEN the story is linked as a child of the Feature
AND the story URL is posted to chat
----
|===


=== FEATURE: Compliance and Tenant-Scoped Operation
[cols="1,3a"]
|===
|*ID*          |FEAT-006
|*Title*       |Keep all processing within the organization’s Azure tenant
|*Description* |Pennie runs on Azure AI Foundry with Azure-hosted models; integration uses Functions/Logic Apps; no third-party AI services are called.
|*User Stories*|
* *As a security lead, I want Pennie to operate entirely within our tenant so that sensitive data never leaves our control boundary.*
**Acceptance Criteria**::
+
----
SCENARIO: Data residency and egress control
GIVEN Pennie processes meeting context and backlog data
WHEN invoking any tools or models
THEN only Azure tenant resources are used (no external endpoints)
AND secrets/credentials are managed via Key Vault / GitHub Encrypted Secrets
----
