2+| *Epic hypothesis*
|*Value statement* |
FOR delivery teams, business analysts, and product owners
WHO struggle to capture and maintain high-quality requirements during fast-paced project meetings
THE Pennie the Prepper for Teams (MVP)
IS A real-time AI agent that joins Microsoft Teams meetings, listens to live conversations with speaker diarization, and generates structured backlog items in Azure DevOps using the T-Minus-15 framework
THAT uses Graph Communications API for real-time audio access, Azure Speech Services for transcription with speaker attribution, and Azure AI Foundry for intelligent requirement extraction
UNLIKE traditional note-taking or manual backlog entry processes that are inconsistent and error-prone, or passive transcript review after meetings
OUR SOLUTION actively listens during meetings, identifies who said what, creates work items tagged with speaker names and timestamps, and posts real-time notifications in Teams chat—all within the organization's secure Azure tenant, improving clarity, reducing rework, and allowing teams to stay focused on meaningful client conversations while Pennie builds a consistent, high-quality backlog behind the scenes.

|*Non-Functional Requirements (NFRs)* |All data must reside within the organization’s Azure tenant and be secure, reliable, and easy to use.

== FEATURES


=== FEATURE: Capture Epics, Features, and User Stories from Meetings
[cols="1,3a"]
|===
|*ID* |FEAT-001
|*Title* |Extract backlog items in real time from meeting transcripts
|*Description* |During live Teams meetings, Pennie listens to the conversation and generates Azure DevOps entries following the T-Minus-15 hierarchy (Epic > Feature > User Story). She uses contextual cues and speaker intent to populate structured metadata.
|*User Stories*|
* *As a project sponsor, I want to receive a summary of captured requirements after each meeting so that I can validate completeness and confirm alignment.*
**Description**:: After each meeting, Pennie posts a summary of new and updated backlog items to the Teams chat, with links and flags for any ambiguous items.
**Acceptance Criteria**::
+
----
SCENARIO: Meeting completion summary
GIVEN a Teams meeting ends
WHEN Pennie finalizes transcript processing
THEN she posts a summary of backlog items and questions to the meeting chat
AND includes links to the corresponding DevOps items
----

* *As a business analyst, I want Pennie to associate conversational context (who said what) with backlog items so that traceability is preserved.*
**Description**:: Pennie tags each created or updated item with speaker name and timestamp from the Teams transcript.
**Acceptance Criteria**::
+
----
SCENARIO: Context tagging for stories
GIVEN a requirement is voiced during the meeting
WHEN Pennie generates a story or feature
THEN she includes the originating speaker and time
AND saves that metadata to the work item
----
|===


=== FEATURE: Ask Clarifying Questions in Chat
[cols="1,3a"]
|===
|*ID* |FEAT-002
|*Title* |Ask structured questions in Teams chat when data is missing
|*Description* |When information is ambiguous or incomplete, Pennie posts polite, concise clarifying questions in Teams chat and logs a linked `Question` work item in Azure DevOps.
|*User Stories*|
* *As a team member, I want Pennie to ask follow-up questions when domain constraints are unclear so that the backlog is less ambiguous.*
**Description**:: Pennie identifies vague or subjective requirements (e.g. “fast”, “user-friendly”) and prompts users for measurable details.
**Acceptance Criteria**::
+
----
SCENARIO: Ambiguous performance requirement
GIVEN a participant says “It needs to be faster”
WHEN Pennie detects missing quantitative detail
THEN she asks a clarifying question such as “What is the current response time target?”
AND logs a linked Question work item in DevOps
----

* *As a UX designer, I want Pennie to ask for example user flows when steps are missing so that stories include usage context.*
**Description**:: Pennie detects workflow-related stories missing step-by-step context and requests a sample flow.
**Acceptance Criteria**::
+
----
SCENARIO: Missing user flow
GIVEN a new story lacks step sequence
WHEN Pennie detects the gap
THEN she asks the speaker to describe a typical user journey
AND attaches that summary to the story item
----
|===


=== FEATURE: Post Real-Time Change Log to Teams Chat
[cols="1,3a"]
|===
|*ID* |FEAT-003
|*Title* |Announce backlog changes with links in chat
|*Description* |Every time Pennie creates or updates an Azure DevOps item, she posts a concise message in Teams chat with the title, link, and a one-line summary of the change.
|*User Stories*|
* *As a stakeholder, I want to see change notifications with clear links so that I can review updates immediately.*
**Description**:: Pennie posts short, readable notifications for each change.
**Acceptance Criteria**::
+
----
SCENARIO: Posting individual change updates
GIVEN a work item is created or edited
WHEN the update is saved
THEN Pennie sends a Teams chat message summarizing the change
AND includes a direct link to the DevOps item
----

* *As a developer, I want Pennie to group multiple quick changes into one summary so chat noise is reduced.*
**Description**:: Pennie batches several related changes into a single notification if they occur within one minute.
**Acceptance Criteria**::
+
----
SCENARIO: Batched change updates
GIVEN three backlog edits occur within thirty seconds
WHEN Pennie detects multiple quick updates
THEN she posts one combined summary message listing all affected items
----
|===


=== FEATURE: Revise and Improve Existing Backlog Items
[cols="1,3a"]
|===
|*ID* |FEAT-004
|*Title* |Review and refine existing backlog items for clarity
|*Description* |Pennie can review existing backlog items and suggest improvements — such as clearer names, more specific acceptance criteria, or corrected classification — during backlog grooming sessions.
|*User Stories*|
* *As a Scrum Master, I want Pennie to propose detailed acceptance criteria for incomplete stories so that each item is testable.*
**Description**:: Pennie detects stories missing Gherkin acceptance criteria and proposes drafts for review.
**Acceptance Criteria**::
+
----
SCENARIO: Suggesting missing acceptance criteria
GIVEN a story lacks any Given/When/Then definitions
WHEN Pennie reviews it during grooming
THEN she proposes new acceptance criteria and logs them as a linked improvement
----

* *As a product owner, I want Pennie to detect misclassified items (task vs story) so that the backlog hierarchy remains consistent.*
**Description**:: Pennie uses linguistic patterns and metadata to identify work items misaligned with their expected type and suggests reclassification.
**Acceptance Criteria**::
+
----
SCENARIO: Detecting misclassified work items
GIVEN a task labeled “Enhance user login flow”
WHEN Pennie analyzes backlog language
THEN she suggests converting it into a User Story or Feature as appropriate
----
|===


=== FEATURE: Azure DevOps CRUD & Hierarchy Linking
[cols="1,3a"]
|===
|*ID* |FEAT-005
|*Title* |Create, read, update, and link DevOps work items with correct hierarchy
|*Description* |Pennie performs all CRUD operations for Epics, Features, User Stories, and Questions, maintaining proper parent-child relationships and traceability between related items.
|*User Stories*|
* *As a system integrator, I want Pennie to validate hierarchy links when moving items so parent-child relationships remain correct.*
**Description**:: Pennie checks all relationships when updating or migrating items between features.
**Acceptance Criteria**::
+
----
SCENARIO: Verifying parent-child links
GIVEN a story is reassigned to another feature
WHEN Pennie performs the update
THEN she validates that the new parent exists and removes obsolete links
----

* *As a QA lead, I want Pennie to retrieve item change history so I can audit backlog evolution.*
**Description**:: Pennie fetches the change log for a specific work item and summarizes it in chat.
**Acceptance Criteria**::
+
----
SCENARIO: Auditing item change history
GIVEN a user asks “Show me history of story #123”
WHEN Pennie calls the GetWorkItems tool
THEN she displays a chronological summary of all changes with timestamps and authors
----
