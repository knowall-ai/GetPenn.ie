= Pennie the Prepper - Troubleshooting Guide

[cols="1,2", options="header"]
|===
| Problem | Solution

| **Pennie calls `read_projects()` but gets empty output**
| Backend is working (returns 26 projects via curl), but Pennie doesn't have the HTTP endpoint URL configured. Open the OpenAPI spec at `/mnt/raid1/GitHub/GetPenn.ie/openapi/pennie-backend-openapi.json` and add it as an Action in Azure AI Foundry portal: Actions → + Add Action → From OpenAPI → Paste spec → Save. Test: "What DevOps projects do we have?"

| **Azure Functions return HTTP 503 "Function host is not running"**
| Python Azure Functions were deployed to Windows Function App. Python requires Linux. Redeploy with `kind: 'functionapp,linux'` and `linuxFxVersion: 'Python|3.11'` in Bicep template. Verify with: `az functionapp show --query "{kind:kind, reserved:reserved}"`

| **Python SDK error: "OpenApiTool is not JSON serializable"**
| Bug in azure-ai-agents SDK v1.0.0. Use the REST API scripts in `scripts/update-pennie-tools.sh` instead of Python SDK until SDK is fixed.

| **Azure AI Foundry Agents fails in UK South**
| Azure AI Agents Service with OpenAPI tools not available in UK South. Use East US 2 (`benw-mgan4638-eastus2`) for Pennie's AI Services account.

| **Backend functions return empty data despite HTTP 200**
| Missing environment variables. Set `AZURE_DEVOPS_ORG` and `AZURE_DEVOPS_PAT` in Function App settings via Bicep or: `az functionapp config appsettings set --settings AZURE_DEVOPS_ORG="KnowAll" AZURE_DEVOPS_PAT="your-token"`

| **Agent can't call functions due to auth errors**
| Functions have `auth_level=FUNCTION` requiring API keys. Change to `auth_level=func.AuthLevel.ANONYMOUS` for agent-callable functions. Configure CORS: `allowedOrigins: ['https://ai.azure.com']`

| **Can't find AI Foundry agent with Azure CLI**
| AI Foundry project agents require specific API version: `2025-05-15-preview`. Endpoint: `https://{resource}.services.ai.azure.com/api/projects/{project}/assistants/{id}?api-version=2025-05-15-preview`. Authentication: `--resource https://ai.azure.com` (NOT cognitiveservices.azure.com). Older API versions like 2024-05-01-preview will return 404 errors.

| **Agent visible in portal but not via OpenAI API**
| AI Foundry agents are PROJECT-scoped, not OpenAI resource-scoped. Use AI Foundry API endpoint (`/api/projects/{project}/assistants`) instead of OpenAI API endpoint (`/openai/assistants`). Agents created at OpenAI resource level won't appear in AI Foundry project portal.

| **Admin consent fails: "Claim is invalid: [permission-id] does not exist on resource application"**
| Graph API permission IDs are incorrect. Verify permission IDs by querying Microsoft Graph service principal: `az ad sp show --id 00000003-0000-0000-c000-000000000000 --query "appRoles[?contains(value, 'Calls')].{Value:value, ID:id}"`. Correct IDs: `Calls.AccessMedia.All` = `a7a681dc-756e-4909-b988-f160edc6655f`, `Calls.JoinGroupCall.All` = `f6b49018-60ab-4f81-83bd-22caeabfed2d`, `OnlineMeetings.ReadWrite.All` = `b8bb2037-6e08-44ac-a4ea-4674e010e2a4`. Delete incorrect permissions: `az ad app permission delete --id <app-id> --api 00000003-0000-0000-c000-000000000000`, then re-add with correct IDs.

| **Azure CLI `az vm run-command invoke` returns "This is a sample script with parameters" instead of actual output**
| The `az vm run-command` is returning template/placeholder text instead of actual PowerShell script execution results. This prevents remote service verification and log checking. **Workaround**: Use RDP to connect directly to VM (`172.166.237.134:3389`) and run verification commands locally in PowerShell. Alternative: Use Azure Bastion for browser-based access. **Issue**: Tracked in GitHub Issue #15. May be related to Azure CLI extension `/home/user/.azure/cliextensions/ai-examples/azext_ai_examples/custom.py` using deprecated `pkg_resources` API.

| **Bot deployed to VM but health endpoint not accessible externally (port 443 timeout)**
| Despite successful deployment and NSG allowing HTTPS (port 443), external health checks timeout. **Likely causes**: (1) Windows service not running, (2) ASP.NET Core listening on different port (check `ASPNETCORE_URLS` env var), (3) Windows Firewall blocking despite rule creation, (4) App listening on localhost only instead of 0.0.0.0. **Troubleshooting**: RDP to VM, run `Get-Service -Name PennieBot` to check status, `Get-NetTCPConnection -State Listen` to verify listening ports, `Get-Content C:\Pennie\logs\bot-stderr.log` for startup errors. **Fix**: If service stopped, run `Start-Service -Name PennieBot`. If listening on wrong port, check Program.cs and configure URLs: `builder.WebHost.UseUrls("http://0.0.0.0:80", "https://0.0.0.0:443")`.

| **Teams Bot not visible in Microsoft Teams for messaging**
| Bot code deployed to VM does not automatically appear in Teams. **Required steps**: (1) Create Azure AD App Registration for bot (Bot Framework portal or Azure Portal), (2) Configure bot credentials (MicrosoftAppId, MicrosoftAppPassword) in VM environment variables or Key Vault, (3) Create Teams App manifest with bot endpoint URL (`https://your-bot-url.com/api/messages`), (4) Upload manifest to Teams App Studio or publish to Teams App Catalog, (5) Add bot to Teams tenant. **Reference**: https://docs.microsoft.com/en-us/microsoftteams/platform/bots/how-to/create-a-bot-for-teams

| **Azure Storage SAS token generation fails with "specify --as-user when --auth-mode login is used"**
| When using `az storage blob generate-sas` with `--auth-mode login`, the `--as-user` flag is required for user delegation SAS tokens. **Error**: `ERROR: incorrect usage: specify --as-user when --auth-mode login is used to get user delegation key.` **Fix**: Add `--as-user` flag to the command: `az storage blob generate-sas --account-name $account --container-name $container --name $blob --permissions r --expiry $expiry --auth-mode login --as-user --full-uri`. This generates a user delegation SAS token using Azure AD credentials instead of account keys.

| **SingleTenant Teams bot - messages not reaching bot endpoint**
| Direct Line works but Teams messages never arrive. **Fix**: (1) Add Bot Framework redirect URI (CRITICAL): `az ad app update --id {app-id} --web-redirect-uris "https://token.botframework.com/.auth/web/redirect"`, (2) Add identifier URI: `az ad app update --id {app-id} --identifier-uris "api://botid-{app-id}"`, (3) Add `webApplicationInfo` to manifest.json: `{"id": "{app-id}", "resource": "api://botid-{app-id}"}`, (4) Regenerate app secret after switching to SingleTenant: `az ad app credential reset --id {app-id}`, (5) Re-upload Teams app and fully restart Teams client.

| **MultiTenant bot creation deprecated**
| `az bot create --app-type MultiTenant` fails with deprecation error. **Fix**: Use `--app-type SingleTenant` with `--msi-resource-id` for managed identity, or use `--app-type UserAssignedMSI`. SingleTenant requires extra configuration (identifier URI, webApplicationInfo in manifest).

| **SingleTenant bot auth mismatch**
| Bot Service is SingleTenant but App Registration is MultiTenant (or vice versa). Causes silent failures. **Verify**: Bot Service: `az bot show --query properties.msaAppType`, App Registration: `az ad app show --query signInAudience`. Both must match: SingleTenant = `AzureADMyOrg`, MultiTenant = `AzureADMultipleOrgs`.

| **SingleTenant bot 401 Unauthorized when replying to messages**
| Bot receives messages but gets `Operation returned an invalid status code 'Unauthorized'` when trying to reply. **Root causes**: (1) Invalid/expired client secret, (2) Missing SingleTenant configuration in appsettings.json. **Diagnose**: Check logs for `401` responses to `directline.botframework.com`. Test secret: `curl -X POST "https://login.microsoftonline.com/{tenant-id}/oauth2/v2.0/token" -d "client_id={app-id}&client_secret={secret}&scope=https://api.botframework.com/.default&grant_type=client_credentials"` - if it returns `AADSTS7000215: Invalid client secret`, create new secret: `az ad app credential reset --id {app-id} --append --years 2`. **Fix SingleTenant config**: Add to appsettings.json: `"MicrosoftAppTenantId": "{tenant-id}"`, `"MicrosoftAppType": "SingleTenant"`. Update Key Vault: `az keyvault secret set --vault-name {vault} --name MicrosoftAppPassword --value "{new-secret}"`. Fully restart bot service after changes.

== AI Foundry Agent API Reference

**Endpoint Structure**:
----
https://{resource-name}.services.ai.azure.com/api/projects/{project-name}/assistants/{assistant-id}?api-version=2025-05-15-preview
----

**For Pennie (East US 2)**:

- *Resource*: benw-mgan4638-eastus2
- *Project*: benw-mgan4638-eastus2_project (Display: T-Minus-15-Agents-US)
- *Assistant ID*: asst_QP4Q94razJnAaC16jjiuDfih
- *API Version*: `2025-05-15-preview` (CRITICAL - do not use 2024-* versions)
- *Authentication Scope*: `https://ai.azure.com` (NOT cognitiveservices.azure.com)

**Key Differences from OpenAI Assistants API**:

- AI Foundry agents are *project-scoped*, not OpenAI resource-scoped
- Different endpoint: `/api/projects/{project}/assistants` vs `/openai/assistants`
- Different auth scope: `https://ai.azure.com` vs `https://cognitiveservices.azure.com`
- Newer API version: `2025-05-15-preview` vs 2024-* versions
- Agents created at OpenAI resource level won't appear in AI Foundry project portal
- Agents created at AI Foundry project level ARE visible in portal
