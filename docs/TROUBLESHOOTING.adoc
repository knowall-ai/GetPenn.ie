= Troubleshooting Guide: Pennie the Prepper

This document contains solutions to common problems encountered when deploying and operating Pennie the Prepper.

== Quick Reference Table

[cols="1,2", options="header"]
|===
|Problem |Solution

|**Bot doesn't join Teams meeting**
a|
1. Check Graph API permissions granted (admin consent required)
2. Verify bot app ID and password in Key Vault
3. Check Windows VM is running: `nssm status PennieBot`
4. Verify firewall allows outbound HTTPS to Teams service
5. Ensure bot was explicitly invited to meeting

|**No transcription / No work items created**
a|
1. Check Azure Speech Services connection and API key
2. Restart MCP service: `nssm restart PennieMCP`
3. Verify AI Foundry agent is connected to MCP server
4. Check meeting audio quality (reduce background noise)
5. Review Application Insights logs for errors

|**Work items missing speaker attribution**
a|
1. Verify Speech Services has diarization enabled (`speakerDiarization: true`)
2. Ensure meeting participants join with authenticated accounts (not anonymous)
3. Improve audio quality (use headsets, reduce echo)
4. Check Speech Services logs for diarization confidence scores

|**Duplicate work items created**
a|
1. Update agent instructions to check existing items before creation
2. Tune semantic similarity matching threshold
3. Implement post-meeting deduplication review
4. Check agent is calling `wit_get_work_item` before `wit_create_work_item`

|**MCP server authentication fails**
a|
1. Clear cached credentials: `Remove-Item -Path "$env:USERPROFILE\.azure-devops-mcp" -Recurse -Force`
2. Re-authenticate: `npx @azure-devops/mcp YourOrg`
3. Ensure user has Azure DevOps project access
4. Check firewall allows HTTPS to `dev.azure.com`

|**MCP server connection errors**
a|
1. Verify Azure DevOps organization name is correct
2. Check network connectivity: `Test-NetConnection dev.azure.com -Port 443`
3. Ensure Windows VM firewall allows outbound HTTPS
4. Restart MCP service: `nssm restart PennieMCP`

|**Deployment fails: Resource already exists**
a|
1. Check parameter file matches existing resource names (e.g., AI Hub)
2. Use existing resources: deployment will update, not recreate
3. If conflict persists, rename resource in parameters or delete existing

|**Key Vault access denied**
a|
1. Grant deployment principal `Key Vault Administrator` or `Key Vault Secrets Officer` role
2. Ensure VM Managed Identity has `Key Vault Secrets User` role
3. Check Key Vault firewall allows Azure services

|**VM Extension installation failed**
a|
1. Check extension logs: `az vm extension show --resource-group TMinus15Agents --vm-name pennie-vm-prod --name InstallDependencies`
2. Retry manually: RDP to VM and run installation script
3. Verify VM has internet access for downloading packages

|**Public IP not accessible**
a|
1. Check Network Security Group allows traffic from your IP
2. Verify Public IP is correctly associated with NIC
3. Check VM is running: `az vm show --resource-group TMinus15Agents --name pennie-vm-prod --show-details`

|**Speech Services transcription errors**
a|
1. Check Speech Services API key is valid
2. Verify audio format: 16kHz, mono, 16-bit PCM
3. Ensure Speech Services region matches deployment region
4. Review Speech Services quota and usage limits

|**AI Foundry agent not responding**
a|
1. Check GPT-4o deployment is active in Azure OpenAI
2. Verify agent configuration in `agent-config.json`
3. Check Application Insights for quota or rate limit errors
4. Ensure MCP server endpoint is reachable from AI Foundry

|**Bot service won't start**
a|
1. Check service logs: `Get-Content C:\Pennie\logs\bot.log -Tail 50`
2. Verify all dependencies installed: Node.js, .NET 8.0
3. Check environment variables are set correctly
4. Ensure port 443 is not already in use: `netstat -ano \| findstr :443`

|**Missing tools in MCP server**
a|
1. Ensure `work-items` domain specified in `mcp-config.json`
2. Verify MCP server version: `npx @azure-devops/mcp --version`
3. Update to latest: `npm update -g @azure-devops/mcp`
4. Restart MCP service after configuration changes

|**GitHub Actions deployment fails**
a|
1. Check GitHub secrets are set correctly: `AZURE_CREDENTIALS`, `AZURE_SUBSCRIPTION_ID`, etc.
2. Verify service principal has Contributor role on subscription
3. Review workflow logs in GitHub Actions tab
4. Ensure Bicep templates are valid: `az bicep build --file infra/main.bicep`

|**Teams chat notifications not appearing**
a|
1. Verify bot has permission to post in meeting chat
2. Check Application Insights for message send errors
3. Ensure Teams app has correct scopes in manifest
4. Test bot messaging with simple "Hello" message

|**Audio quality poor / garbled transcription**
a|
1. Ask participants to use headsets instead of speakers
2. Reduce background noise (close windows, mute when not speaking)
3. Check network bandwidth for audio streaming
4. Verify RTP audio frames are being received correctly

|**Costs higher than expected**
a|
1. Review Azure Cost Management dashboard for breakdown
2. Check Speech Services usage (charged per hour of audio)
3. Verify VM is not oversized (downsize if CPU <30%)
4. Ensure logs retention not set too high (reduce to 30 days)
5. Monitor OpenAI token usage in Application Insights

|**Agent creates wrong work item type**
a|
1. Review and refine agent instructions in `agent-config.json`
2. Provide clearer examples in system prompt
3. Increase temperature slightly for more creative classification (0.1 → 0.2)
4. Add explicit keywords to meeting discussion ("This is an epic...")

|**Meeting transcripts not captured**
a|
1. Verify bot joined meeting successfully (check Teams)
2. Check Audio stream connection to Speech Services
3. Review Speech Services logs for errors
4. Ensure Speech Services has sufficient quota

|**DevOps work items have incorrect fields**
a|
1. Check work item type templates in Azure DevOps project
2. Verify MCP server has correct field mappings
3. Update agent instructions to include required fields
4. Test with minimal work item creation first

|===

== Detailed Diagnostics

=== Checking Bot Service Health

```powershell
# Check service status
nssm status PennieBot

# View recent logs
Get-Content C:\Pennie\logs\bot.log -Tail 100 -Wait

# Check process details
Get-Process -Name PennieBot

# Test health endpoint
Invoke-WebRequest -Uri http://localhost/health
```

=== Checking MCP Server Health

```powershell
# Check service status
nssm status PennieMCP

# View recent logs
Get-Content C:\Pennie\logs\mcp.log -Tail 100 -Wait

# Test connection
npx @azure-devops/mcp YourOrg --test

# List available tools
npx @azure-devops/mcp YourOrg --list-tools
```

=== Checking Azure Services

```bash
# Check Speech Services status
az cognitiveservices account show \
  --name pennie-speech-prod \
  --resource-group TMinus15Agents

# Check OpenAI deployment
az cognitiveservices account deployment show \
  --name pennie-openai-prod \
  --resource-group TMinus15Agents \
  --deployment-name gpt-4o

# Check VM status
az vm show \
  --name pennie-vm-prod \
  --resource-group TMinus15Agents \
  --show-details
```

=== Application Insights Queries

```kusto
// Bot errors in last hour
traces
| where timestamp > ago(1h)
| where severityLevel >= 3
| where message contains "PennieBot"
| order by timestamp desc

// Work items created today
traces
| where timestamp > startofday(now())
| where message contains "Created work item"
| summarize count() by tostring(customDimensions.WorkItemType)

// Meeting join events
traces
| where timestamp > ago(24h)
| where message contains "JoinMeeting"
| project timestamp, message, customDimensions
```

== Getting Help

If troubleshooting steps don't resolve the issue:

1. **Check Application Insights** for detailed error logs
2. **Review GitHub Issues** for similar problems: https://github.com/benweeks/GetPenn.ie/issues
3. **Open a new issue** with:
   - Problem description
   - Steps to reproduce
   - Logs from Application Insights
   - Environment details (region, versions)
4. **Contact support**: ben.weeks@outlook.com

== Preventive Measures

To avoid common issues:

- ✅ Use headsets in meetings for better audio quality
- ✅ Ensure participants join with authenticated accounts (not anonymous)
- ✅ Monitor Application Insights daily for errors
- ✅ Keep MCP server and dependencies updated
- ✅ Rotate secrets regularly (every 90 days)
- ✅ Test deployments in TEST environment before PROD
- ✅ Review work item quality weekly and refine agent instructions
