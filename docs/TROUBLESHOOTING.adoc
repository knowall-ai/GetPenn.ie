= Pennie the Prepper - Troubleshooting Guide

[cols="1,2", options="header"]
|===
| Problem | Solution

| **Pennie calls `read_projects()` but gets empty output**
| Backend is working (returns 26 projects via curl), but Pennie doesn't have the HTTP endpoint URL configured. Open the OpenAPI spec at `/mnt/raid1/GitHub/GetPenn.ie/openapi/pennie-backend-openapi.json` and add it as an Action in Azure AI Foundry portal: Actions → + Add Action → From OpenAPI → Paste spec → Save. Test: "What DevOps projects do we have?"

| **Azure Functions return HTTP 503 "Function host is not running"**
| Python Azure Functions were deployed to Windows Function App. Python requires Linux. Redeploy with `kind: 'functionapp,linux'` and `linuxFxVersion: 'Python\|3.11'` in Bicep template. Verify with: `az functionapp show --query "{kind:kind, reserved:reserved}"`

| **Python SDK error: "OpenApiTool is not JSON serializable"**
| Bug in azure-ai-agents SDK v1.0.0. Use the REST API scripts in `scripts/update-pennie-tools.sh` instead of Python SDK until SDK is fixed.

| **Azure AI Foundry Agents fails in UK South**
| Azure AI Agents Service with OpenAPI tools not available in UK South. Use East US 2 (`benw-mgan4638-eastus2`) for Pennie's AI Services account.

| **Backend functions return empty data despite HTTP 200**
| Missing environment variables. Set `AZURE_DEVOPS_ORG` and `AZURE_DEVOPS_PAT` in Function App settings via Bicep or: `az functionapp config appsettings set --settings AZURE_DEVOPS_ORG="KnowAll" AZURE_DEVOPS_PAT="your-token"`

| **Agent can't call functions due to auth errors**
| Functions have `auth_level=FUNCTION` requiring API keys. Change to `auth_level=func.AuthLevel.ANONYMOUS` for agent-callable functions. Configure CORS: `allowedOrigins: ['https://ai.azure.com']`

| **Can't find AI Foundry agent with Azure CLI**
| AI Foundry project agents require specific API version: `2025-05-15-preview`. Endpoint: `https://{resource}.services.ai.azure.com/api/projects/{project}/assistants/{id}?api-version=2025-05-15-preview`. Authentication: `--resource https://ai.azure.com` (NOT cognitiveservices.azure.com). Older API versions like 2024-05-01-preview will return 404 errors.

| **Agent visible in portal but not via OpenAI API**
| AI Foundry agents are PROJECT-scoped, not OpenAI resource-scoped. Use AI Foundry API endpoint (`/api/projects/{project}/assistants`) instead of OpenAI API endpoint (`/openai/assistants`). Agents created at OpenAI resource level won't appear in AI Foundry project portal.

| **Admin consent fails: "Claim is invalid: [permission-id] does not exist on resource application"**
| Graph API permission IDs are incorrect. Verify permission IDs by querying Microsoft Graph service principal: `az ad sp show --id 00000003-0000-0000-c000-000000000000 --query "appRoles[?contains(value, 'Calls')].{Value:value, ID:id}"`. Correct IDs: `Calls.AccessMedia.All` = `a7a681dc-756e-4909-b988-f160edc6655f`, `Calls.JoinGroupCall.All` = `f6b49018-60ab-4f81-83bd-22caeabfed2d`, `OnlineMeetings.ReadWrite.All` = `b8bb2037-6e08-44ac-a4ea-4674e010e2a4`. Delete incorrect permissions: `az ad app permission delete --id <app-id> --api 00000003-0000-0000-c000-000000000000`, then re-add with correct IDs.

| **Azure CLI `az vm run-command invoke` returns "This is a sample script with parameters" instead of actual output**
| The `az vm run-command` is returning template/placeholder text instead of actual PowerShell script execution results. This prevents remote service verification and log checking. **Workaround**: Use RDP to connect directly to VM (`172.166.237.134:3389`) and run verification commands locally in PowerShell. Alternative: Use Azure Bastion for browser-based access. **Issue**: Tracked in GitHub Issue #15. May be related to Azure CLI extension `/home/user/.azure/cliextensions/ai-examples/azext_ai_examples/custom.py` using deprecated `pkg_resources` API.

| **Bot deployed to VM but health endpoint not accessible externally (port 443 timeout)**
| Despite successful deployment and NSG allowing HTTPS (port 443), external health checks timeout. **Likely causes**: (1) Windows service not running, (2) ASP.NET Core listening on different port (check `ASPNETCORE_URLS` env var), (3) Windows Firewall blocking despite rule creation, (4) App listening on localhost only instead of 0.0.0.0. **Troubleshooting**: RDP to VM, run `Get-Service -Name PennieBot` to check status, `Get-NetTCPConnection -State Listen` to verify listening ports, `Get-Content C:\Pennie\logs\bot-stderr.log` for startup errors. **Fix**: If service stopped, run `Start-Service -Name PennieBot`. If listening on wrong port, check Program.cs and configure URLs: `builder.WebHost.UseUrls("http://0.0.0.0:80", "https://0.0.0.0:443")`.

| **Teams Bot not visible in Microsoft Teams for messaging**
| Bot code deployed to VM does not automatically appear in Teams. **Required steps**: (1) Create Azure AD App Registration for bot (Bot Framework portal or Azure Portal), (2) Configure bot credentials (MicrosoftAppId, MicrosoftAppPassword) in VM environment variables or Key Vault, (3) Create Teams App manifest with bot endpoint URL (`https://your-bot-url.com/api/messages`), (4) Upload manifest to Teams App Studio or publish to Teams App Catalog, (5) Add bot to Teams tenant. **Reference**: https://docs.microsoft.com/en-us/microsoftteams/platform/bots/how-to/create-a-bot-for-teams

| **Azure Storage SAS token generation fails with "specify --as-user when --auth-mode login is used"**
| When using `az storage blob generate-sas` with `--auth-mode login`, the `--as-user` flag is required for user delegation SAS tokens. **Error**: `ERROR: incorrect usage: specify --as-user when --auth-mode login is used to get user delegation key.` **Fix**: Add `--as-user` flag to the command: `az storage blob generate-sas --account-name $account --container-name $container --name $blob --permissions r --expiry $expiry --auth-mode login --as-user --full-uri`. This generates a user delegation SAS token using Azure AD credentials instead of account keys.

| **SingleTenant Teams bot - messages not reaching bot endpoint**
| Direct Line works but Teams messages never arrive. **Fix**: (1) Add Bot Framework redirect URI (CRITICAL): `az ad app update --id {app-id} --web-redirect-uris "https://token.botframework.com/.auth/web/redirect"`, (2) Add identifier URI: `az ad app update --id {app-id} --identifier-uris "api://botid-{app-id}"`, (3) Add `webApplicationInfo` to manifest.json: `{"id": "{app-id}", "resource": "api://botid-{app-id}"}`, (4) Regenerate app secret after switching to SingleTenant: `az ad app credential reset --id {app-id}`, (5) Re-upload Teams app and fully restart Teams client.

| **Teams App Graph API upload/update fails with 403 Forbidden**
| When publishing or updating Teams app via Graph API, returns "User not authorized to perform this operation". **Root cause**: Microsoft Graph API restricts Teams app catalog operations. App ownership is tied to the uploader. **Key limitations**: (1) Service principals can only update apps they uploaded, (2) Apps uploaded manually via Teams Admin Center are owned by the admin user, not a service principal, (3) Azure CLI tokens don't include `AppCatalog.*` scopes. **Solution**: Manage Teams apps via Teams Admin Center: https://admin.teams.microsoft.com > Teams apps > Manage apps. Upload new versions manually when needed. **Package location**: `bot/teams-manifest/pennie-app-v1.1.0.zip`.

| **MultiTenant bot creation deprecated**
| `az bot create --app-type MultiTenant` fails with deprecation error. **Fix**: Use `--app-type SingleTenant` with `--msi-resource-id` for managed identity, or use `--app-type UserAssignedMSI`. SingleTenant requires extra configuration (identifier URI, webApplicationInfo in manifest).

| **CS0712: Cannot create an instance of the static class 'MediaPlatform'**
| Using `new MediaPlatform()` in code. `MediaPlatform` is a **static class** in `Microsoft.Skype.Bots.Media`. **Fix**: Use `MediaPlatform.Initialize(settings)` instead of instantiation. For shutdown, use `MediaPlatform.Shutdown()` instead of instance methods.

| **Graph API error 9999 when joining call with ApplicationHostedMedia**
| Using custom JSON for `AppHostedMediaConfig.Blob` instead of SDK-generated blob. The blob contains binary-encoded configuration (audio socket bindings, certificate fingerprints, media session config). **Fix**: Use `JObject mediaConfig = MediaPlatform.CreateMediaConfiguration(audioSocket); string blob = mediaConfig.ToString();` to generate the correctly formatted blob.

| **AudioSocket constructor error: does not contain a constructor that takes 2 arguments**
| Passing logger as second argument to `AudioSocket` constructor. The SDK only accepts `AudioSocketSettings`. **Fix**: Use `var audioSocket = new AudioSocket(audioSettings);` with a single argument. The SDK handles its own internal logging.

| **MediaPlatform "needs a system with at least 2 cores" error**
| VM has insufficient physical cores. Standard_D2s_v3 has 2 vCPUs but only 1 physical core (hyperthreaded). MediaPlatform SDK requires 2+ physical cores. **Fix**: Upgrade VM to Standard_D4s_v3 (4 vCPUs = 2 physical cores, ~£140/month): `az vm deallocate -g TMinus15Agents -n pennie-vm-prod && az vm resize -g TMinus15Agents -n pennie-vm-prod --size Standard_D4s_v3 && az vm start -g TMinus15Agents -n pennie-vm-prod`. Enable ApplicationHostedMedia in Key Vault: `az keyvault secret set --vault-name pennie-kv-mmdxqm3w7kjwm --name "MediaPlatform--UseApplicationHostedMedia" --value "true"`.

| **AudioSocket CallId error: "Value cannot be null or empty"**
| AudioSocketSettings.CallId is required by AudioSocket constructor but not being set. **Fix**: Set CallId when creating AudioSocketSettings: `var settings = new AudioSocketSettings { CallId = callId ?? Guid.NewGuid().ToString(), StreamDirections = StreamDirection.Recvonly, SupportedAudioFormat = AudioFormat.Pcm16K, ReceiveUnmixedMeetingAudio = true };`

| **ApplicationHostedMedia call terminates immediately after "establishing"**
| Missing network rules for media streams. ApplicationHostedMedia requires specific ports. **Fix**: Add Azure NSG rules: `az network nsg rule create -g TMinus15Agents --nsg-name pennie-nsg-prod -n AllowMediaSignaling --priority 130 --direction Inbound --access Allow --protocol Tcp --destination-port-ranges 8445` and `az network nsg rule create -g TMinus15Agents --nsg-name pennie-nsg-prod -n AllowMediaRTP --priority 140 --direction Inbound --access Allow --protocol Udp --destination-port-ranges "20000-20100"`. Add Windows Firewall rules on VM: `New-NetFirewallRule -DisplayName "MediaPlatform Signaling" -Direction Inbound -Protocol TCP -LocalPort 8445 -Action Allow` and `New-NetFirewallRule -DisplayName "MediaPlatform RTP" -Direction Inbound -Protocol UDP -LocalPort 20000-20100 -Action Allow`.

| **SingleTenant bot auth mismatch**
| Bot Service is SingleTenant but App Registration is MultiTenant (or vice versa). Causes silent failures. **Verify**: Bot Service: `az bot show --query properties.msaAppType`, App Registration: `az ad app show --query signInAudience`. Both must match: SingleTenant = `AzureADMyOrg`, MultiTenant = `AzureADMultipleOrgs`.

| **SingleTenant bot 401 Unauthorized when replying to messages**
| Bot receives messages but gets `Operation returned an invalid status code 'Unauthorized'` when trying to reply. **Root causes**: (1) Invalid/expired client secret, (2) Missing SingleTenant configuration in appsettings.json. **Diagnose**: Check logs for `401` responses to `directline.botframework.com`. Test secret: `curl -X POST "https://login.microsoftonline.com/{tenant-id}/oauth2/v2.0/token" -d "client_id={app-id}&client_secret={secret}&scope=https://api.botframework.com/.default&grant_type=client_credentials"` - if it returns `AADSTS7000215: Invalid client secret`, create new secret: `az ad app credential reset --id {app-id} --append --years 2`. **Fix SingleTenant config**: Add to appsettings.json: `"MicrosoftAppTenantId": "{tenant-id}"`, `"MicrosoftAppType": "SingleTenant"`. Update Key Vault: `az keyvault secret set --vault-name {vault} --name MicrosoftAppPassword --value "{new-secret}"`. Fully restart bot service after changes.

| **Pennie app not found when searching in meeting Apps panel**
| When searching "pennie" in the meeting Apps panel, it shows "No results found". **Fix**: Click **"Get more apps"** button at the bottom of the search results - this opens the full app catalog where Pennie will be visible. The built-in search only shows a subset of installed apps. Alternatively, pre-pin Pennie to the meeting before it starts via the meeting details page.

| **Speech transcription receives zero-filled audio buffers (all zeros)**
| With `ReceiveUnmixedMeetingAudio = true`, audio data is in `buffer.UnmixedAudioBuffers`, NOT in `buffer.Data`. The `buffer.Data` property is empty/zeros when using unmixed mode. **Root cause**: Code was reading `buffer.Data` but unmixed per-speaker audio is delivered in `buffer.UnmixedAudioBuffers` array. Each `UnmixedAudioBuffer` contains: `Data` (IntPtr), `Length` (Int64), `ActiveSpeakerId` (UInt32). **Fix**: Iterate through `buffer.UnmixedAudioBuffers` instead of reading `buffer.Data` directly: `foreach (var unmixedBuffer in buffer.UnmixedAudioBuffers) { var audioData = new byte[unmixedBuffer.Length]; Marshal.Copy(unmixedBuffer.Data, audioData, 0, (int)unmixedBuffer.Length); }`. **Diagnostic symptoms**: AUDIO-ANALYSIS logs show `LastRMS=0, MaxSample=0, NonZero=0/320` despite frames being received. Speech SDK `SessionStarted` fires but `SpeechStartDetected` never fires. **Reference**: https://microsoftgraph.github.io/microsoft-graph-comms-samples/docs/bot_media/Microsoft.Skype.Bots.Media.UnmixedAudioBuffer.html

| **Audio receiving but no transcription output**
| Audio packets forwarded to Speech Services but no transcription results returned. **Diagnostic**: Check AUDIO-ANALYSIS logs for RMS values: `LastRMS=15-50` indicates very quiet/silent audio. **Root cause**: Microphone volume too low or muted in Teams settings. Azure Speech Services requires adequate audio signal strength (RMS > 100) to detect speech. **Fix**: Increase microphone volume in Windows Sound Settings or Teams device settings. **RMS reference values**: RMS ~15-50 = near silence, RMS ~100-300 = normal speech, RMS >500 = loud speech. Also ensure: (1) correct microphone selected in Teams, (2) microphone not muted, (3) no background noise suppression reducing legitimate speech.

| **Azure Key Vault config keys not matching code (dashes vs underscores)**
| Code uses `_configuration["AZURE_OPENAI_ENDPOINT"]` but Key Vault has `AZURE-OPENAI-ENDPOINT`. **Root cause**: Azure Key Vault doesn't allow underscores in secret names, so dashes are used. However, the Azure Key Vault configuration provider does NOT automatically convert dashes to underscores. **Fix**: Use dashes in code to match Key Vault: `_configuration["AZURE-OPENAI-ENDPOINT"]`. This applies to all Key Vault secrets. Check existing code patterns (e.g., `AZURE-SPEECH-KEY` already uses dashes).

| **Azure.AI.OpenAI.Assistants SDK returns 404 "No assistant found"**
| SDK calls succeed but assistant not found despite existing in AI Foundry portal. **Root cause**: AI Foundry PROJECT agents (created via AI Foundry portal) use different API path (`/api/projects/{project}/assistants`) than OpenAI resource assistants (`/openai/assistants`). The `Azure.AI.OpenAI.Assistants` SDK only queries the OpenAI resource level. **Fix**: Either (1) create assistant at OpenAI resource level: `az rest --method POST --url "https://{resource}.openai.azure.com/openai/assistants?api-version=2024-05-01-preview" --resource https://cognitiveservices.azure.com --body @assistant.json`, or (2) use the AI Foundry Agents SDK instead. **Verify existing assistants**: `az rest --method GET --url "https://{resource}.openai.azure.com/openai/assistants?api-version=2024-05-01-preview" --resource https://cognitiveservices.azure.com`.

| **SingleTenant bot AADSTS700016: Application not found in directory**
| Bot receives messages but fails to reply with error: "Application with identifier '{app-id}' was not found in the directory '{tenant-id}'". **Root cause**: SingleTenant bot missing `MicrosoftAppType` configuration. Without it, the SDK defaults to multi-tenant token acquisition, which queries the wrong tenant. **Fix**: Add BOTH settings to Key Vault or appsettings.json: `MicrosoftAppType` = `SingleTenant` AND `MicrosoftAppTenantId` = `{your-tenant-id}`. **Key Vault**: `az keyvault secret set --vault-name {vault} --name MicrosoftAppType --value SingleTenant`. Restart bot after changes.

| **VM managed identity 401 PermissionDenied on Azure OpenAI Assistants API**
| Bot uses `DefaultAzureCredential` but gets: "The principal lacks the required data action `Microsoft.CognitiveServices/accounts/OpenAI/assistants/threads/write`". **Root cause**: VM's managed identity doesn't have RBAC permission on the Azure OpenAI resource. **Fix**: Grant `Cognitive Services OpenAI Contributor` role: `az role assignment create --assignee {vm-managed-identity-principal-id} --role "Cognitive Services OpenAI Contributor" --scope "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.CognitiveServices/accounts/{openai-resource}"`. Get VM principal ID: `az vm show -g {rg} -n {vm} --query "identity.principalId" -o tsv`. Restart bot after granting role.

| **Storage account SAS URL fails with "Public access is not permitted"**
| Deployment script generates SAS URL but VM can't download: "Public access is not permitted on this storage account". **Root cause**: Storage account has `allowBlobPublicAccess: false`. SAS tokens should still work but may require account key authentication. **Fix options**: (1) Enable public blob access: `az storage account update --name {account} --allow-blob-public-access true`, (2) Generate SAS with account key: `az storage blob generate-sas --account-name {account} --account-key "{key}" --container-name {container} --name {blob} --permissions r --expiry {expiry} --full-uri`, (3) Use managed identity with Storage Blob Data Reader role instead of SAS.

| **Test VM bot not responding to Teams messages (only listens on localhost:5000)**
| Production bot works but test VM bot doesn't respond. **Diagnostic**: Check listening ports on VM: `netstat -an \| findstr LISTEN`. Prod shows `0.0.0.0:443` and `0.0.0.0:5000`, test only shows `127.0.0.1:5000`. **Root cause**: Test VM missing SSL certificate and HTTPS binding. Teams requires HTTPS endpoint. Production has SSL cert bound via `netsh http add sslcert`. **Fix**: Deploy workflow now includes Step 7 that automatically: (1) Creates self-signed SSL certificate for VM FQDN, (2) Binds cert to port 443 via `netsh http add sslcert ipport=0.0.0.0:443`, (3) Sets `ASPNETCORE_URLS=https://0.0.0.0:443;http://0.0.0.0:5000`. Re-run deploy workflow for test environment to apply. **Manual fix**: RDP to VM and run: `$cert = New-SelfSignedCertificate -DnsName "{vm-fqdn}" -CertStoreLocation Cert:\LocalMachine\My; netsh http add sslcert ipport=0.0.0.0:443 certhash=$($cert.Thumbprint) appid='{00000000-0000-0000-0000-000000000000}'; [Environment]::SetEnvironmentVariable('ASPNETCORE_URLS', 'https://0.0.0.0:443;http://0.0.0.0:5000', 'Machine'); Restart-Service PennieBot`.

| **RDP access open to internet (security vulnerability)**
| Azure NSG allows RDP (port 3389) from any IP (`sourceAddressPrefix: '*'`). **Fix**: Bicep now uses `allowedRdpSourceIP` parameter. If not provided, RDP rule is not created (secure default). To enable RDP for your dynamic IP: (1) Set GitHub Secret `ADMIN_DDNS_HOSTNAME` to your dynamic DNS hostname (e.g., `robotechy.ddns.net`), (2) Deploy workflow resolves hostname to IP at deploy time, (3) NSG rule created allowing only that IP. **Manual update**: `az network nsg rule update -g {rg} --nsg-name {nsg} -n AllowRDP --source-address-prefixes {your-ip}`.

| **Hardcoded VM password in Bicep template (security vulnerability)**
| VM admin password was hardcoded in `windows-vm.bicep` as `P@ssw0rd!${uniqueString(...)}`. **Fix**: Password now uses `@secure() param adminPassword` requiring `VM_ADMIN_PASSWORD` GitHub Secret. VM deployment fails if secret not set (secure by design). **Set secret**: `gh secret set VM_ADMIN_PASSWORD --env test` and `gh secret set VM_ADMIN_PASSWORD --env prod`.

| **Test bot endpoint healthy but Teams messages fail (missing Azure Bot registration)**
| Endpoint tests pass (`./tests/bot-endpoint-test.sh test` shows healthy), Direct Line works for prod, but test environment Teams messages show "Failed to send". **Root cause**: No Azure Bot Service registration exists for the test environment. The bot VM is deployed and running, but without a Bot Service registration, Teams has no way to route messages to the bot endpoint. Production has `pennie-bot` registration, test has none. **Diagnostic**: `az resource list --resource-type "Microsoft.BotService/botServices" -o table` shows only prod bot. **Fix**: Deploy workflow now includes "Ensure Azure Bot registration exists" step that: (1) Checks if `pennie-bot-{env}` exists, (2) Creates it if missing with correct endpoint URL, (3) Enables Teams channel. Re-run deploy workflow for test environment: `gh workflow run deploy.yml -f environment=test`. **Manual fix**: `az bot create --resource-group TMinus15Agents-Test --name pennie-bot-test --kind registration --sku F0 --appid {TEAMS_APP_ID} --endpoint "https://{vm-fqdn}/api/messages"` then `az bot msteams create --resource-group TMinus15Agents-Test --name pennie-bot-test`.
