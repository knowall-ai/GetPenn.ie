== Overview

This guide provides step-by-step instructions for deploying Pennie the Prepper to your Azure environment. The deployment process is largely automated through scripts and Bicep templates, with a few manual steps for security approvals.

**Current Status** (November 2025): Infrastructure (Phase 1) ✅ complete. Teams bot integration (Phase 2) ✅ deployed with Key Vault integration.

== Step 2: Infrastructure Deployment

=== Deploy Windows Server VM

The Windows VM will host the Teams Media Bot with Graph Communications SDK.

Create parameters file (`infra/windows-vm.parameters.json`):

NOTE: Replace placeholder values with your actual Azure resource names. If you deployed infrastructure first, use those resource names (e.g., Key Vault will have a generated name like `pennie-kv-{uniqueId}`).

[source,json]
----
{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentParameters.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {
    "location": {
      "value": "uksouth"
    },
    "environmentName": {
      "value": "prod"
    },
    "keyVaultName": {
      "value": "pennie-kv-{uniqueId}"
    },
    "applicationInsightsConnectionString": {
      "value": "InstrumentationKey=...;IngestionEndpoint=..."
    },
    "devOpsOrg": {
      "value": "YourOrgName"
    },
    "devOpsProject": {
      "value": "YourProjectName"
    },
    "tags": {
      "value": {
        "Project": "Pennie",
        "Environment": "Production",
        "ManagedBy": "Bicep",
        "Purpose": "Teams Bot VM"
      }
    }
  }
}
----

Deploy the VM:

[source,bash]
----
az deployment group create \
  --resource-group TMinus15Agents \
  --template-file infra/modules/windows-vm.bicep \
  --parameters @infra/windows-vm.parameters.json \
  --name pennie-vm-deployment-$(date +%Y%m%d-%H%M%S)
----

**Deployment Time**: ~3-4 minutes

**Resources Created**:

* VM: Standard_D2s_v3 (2 vCPU, 8 GB RAM)
* OS: Windows Server 2022 Datacenter
* Storage: Premium SSD (128 GB OS disk)
* Network: Public IP with DNS name
* Extensions: Node.js, .NET SDK, Azure DevOps MCP
* Managed Identity: System-assigned with Key Vault access

**Post-Deployment Outputs**:

The deployment will output:

* `vmName`: Virtual machine name
* `vmPublicIP`: Public IP address
* `vmFQDN`: Fully qualified domain name
* `vmPrivateIP`: Private IP within VNet
* `vmPrincipalId`: Managed identity object ID

Save these values for later steps.

== Step 3: Bot App Registration

=== Automated Setup (Recommended)

Run the setup script to create Azure AD app registration:

[source,bash]
----
./scripts/setup-bot-app-registration.sh
----

This script:

1. Creates Azure AD app registration
2. Adds Microsoft Graph API permissions:
   * `Calls.AccessMedia.All` - Access media streams in calls
   * `Calls.JoinGroupCall.All` - Join group calls and meetings
   * `OnlineMeetings.ReadWrite.All` - Read and create online meetings
3. Generates client secret (2-year expiration)
4. Stores credentials in Azure Key Vault
5. Updates `.env` file

**Script Output**:

The script will display the app ID and provide instructions for admin consent.

=== Manual Admin Consent (REQUIRED)

Admin consent for Graph API permissions **cannot be automated** and must be granted manually.

**Azure Portal Method** (Recommended):

1. Navigate to: https://portal.azure.com/
2. Go to: **Entra ID** > **App Registrations** > **Pennie the Prepper Bot**
3. Select: **API Permissions**
4. Click: **Grant admin consent for [Your Organization]**
5. Confirm the consent prompt

IMPORTANT: You must be a Global Administrator or Privileged Role Administrator to grant admin consent.

=== Verify Permissions

After granting consent, verify in Azure Portal:

* All three permissions should show **Status: Granted for [Your Organization]**
* Green checkmarks should appear next to each permission

=== Manual Setup (Alternative)

If the automated script fails, you can create the app registration manually:

1. **Create App Registration**:
   - Azure Portal > Entra ID > App Registrations > New registration
   - Name: "Pennie the Prepper Bot"
   - Supported account types: Single tenant
   - Register

2. **Add API Permissions**:
   - API Permissions > Add permission > Microsoft Graph > Application permissions
   - Add: `Calls.AccessMedia.All`, `Calls.JoinGroupCall.All`, `OnlineMeetings.ReadWrite.All`
   - Grant admin consent

3. **Create Client Secret**:
   - Certificates & secrets > New client secret
   - Description: "PennieBot-Prod-Secret"
   - Expires: 24 months
   - Copy the secret value (only shown once)

4. **Store in Key Vault**:
   [source,bash]
   ----
   az keyvault secret set --vault-name <your-key-vault> --name "TEAMS-APP-ID" --value "<app-id>"
   az keyvault secret set --vault-name <your-key-vault> --name "TEAMS-APP-PASSWORD" --value "<secret>"
   ----

5. **Update .env**:
   Add the app ID and password to your `.env` file.

== Step 5: Deploy Teams Bot

The Teams bot is now fully implemented and ready for deployment to Windows Server VM.

=== What Was Built

The Teams bot includes all critical components:

1. **Graph Communications SDK Integration**: Meeting join/leave with RTP audio capture
2. **Azure Speech Services**: Real-time transcription with speaker diarization
3. **Function Call Handler**: Intercepts Pennie's `requires_action` and calls backend
4. **Service Wiring**: All components connected via dependency injection

=== Architecture Note: Function Calling Pattern

OpenAI Assistants use a **function calling pattern**, not HTTP tools:

**How It Works**:

1. Pennie receives transcript and calls a function (e.g., `read_projects()`)
2. Azure OpenAI returns `requires_action` status
3. **Function Call Handler** (in `PennieAgentClient.cs`):
   * Monitors run status in polling loop
   * Detects `requires_action` status
   * Calls backend: `https://pennie-backend-prod.azurewebsites.net/api/read_projects`
   * Gets the response (26 projects)
   * Submits result back to Pennie via Runs API
4. Pennie processes result and creates work items

=== Automated Deployment

Deploy the bot from your local machine using the automated script:

[source,bash]
----
# Deploy bot to Windows VM
./scripts/deploy-bot.sh
----

**What This Does**:

1. Loads configuration from `.env` (only needs `AZURE_KEY_VAULT_NAME`)
2. Builds bot locally with .NET SDK
3. Publishes for Windows (`win-x64`, self-contained)
4. Injects Key Vault name into `appsettings.json`
5. Creates deployment package (ZIP ~65MB)
6. Uploads to Azure Blob Storage
7. Generates SAS URL (1-hour expiry)
8. Deploys to VM via `az vm run-command invoke`:
   - Stops PennieBot service
   - **Backs up appsettings.json** (preserves VM configuration)
   - Downloads and extracts new version
   - **Restores appsettings.json from backup**
   - Starts PennieBot service
9. Verifies health endpoint

=== Configuration Preservation During Deployment

**CRITICAL**: The deployment process preserves `appsettings.json` on the VM.

The VM's `appsettings.json` contains environment-specific configuration that must not be overwritten:

[source,json]
----
{
  "MicrosoftAppId": "<your-bot-app-id>",
  "MicrosoftAppTenantId": "<your-tenant-id>",
  "MicrosoftAppType": "SingleTenant",
  "AZURE_KEY_VAULT_NAME": "<your-key-vault-name>"
}
----

**Why This Matters**:

* The deployed package contains default/template values, not production configuration
* Without backup/restore, deployment would break the bot's authentication
* Secrets (MicrosoftAppPassword) remain in Key Vault - only non-secrets in appsettings.json

**Both deployment methods preserve the configuration**:

1. **GitHub Actions** (`.github/workflows/deploy.yml`): Backs up before extract, restores after
2. **Local script** (`scripts/deploy-bot-to-vm.ps1`): Backs up before build, restores after

**Key Vault Integration**:

The bot loads credentials from Key Vault at runtime using managed identity:

* `MicrosoftAppId` - Bot Framework App ID
* `MicrosoftAppPassword` - Bot Framework App Password
* `AZURE-FUNCTIONS-BACKEND-URL` - Backend API URL (optional)

**No credentials are stored in** `.env` **or** `appsettings.json` **- only the Key Vault name**.

**Duration**: ~2-3 minutes

**Requirements**:
* .NET 8.0 SDK installed locally
* Azure CLI logged in (`az login`)
* `jq` installed (for JSON manipulation)
* Windows VM already deployed with managed identity
* Key Vault secrets configured (Step 3)

== Troubleshooting

=== VM Deployment Fails

**Error**: Missing required parameter

**Solution**: Ensure `infra/windows-vm.parameters.json` has all required parameters including `tags`.

=== Backend Returns 503

**Error**: Function host is not running

**Solution**: Verify Function App is running on **Linux**, not Windows. Python Azure Functions require Linux.

[source,bash]
----
az functionapp show --name pennie-backend-prod \
  --resource-group TMinus15Agents \
  --query "reserved" -o tsv
----

Should return `true` (Linux). If `false`, redeploy with correct OS.

=== Admin Consent Fails

**Error**: Consent validation failed

**Solution**: Manual admin consent required via Azure Portal. Automated consent via CLI often fails due to Graph API restrictions.

=== Agent Function Calls Return Empty

**Error**: Pennie calls functions but gets empty output in playground

**Root Cause**: Function Call Handler not deployed. This is EXPECTED at this stage.

**Solution**: Deploy Teams Bot with Function Call Handler (Issue #4).

=== Key Vault Access Denied

**Error**: Forbidden - Caller is not authorized

**Solution**: Grant yourself Key Vault Secrets Officer role:

[source,bash]
----
az role assignment create \
  --role "Key Vault Secrets Officer" \
  --assignee <your-email> \
  --scope "<key-vault-resource-id>"
----

Wait 10 seconds for role propagation, then retry.

== Security Considerations

=== Data Residency

* All components deployed within your Azure tenant
* Audio processing in UK South (configurable)
* No data leaves your tenant boundary
* GDPR compliant with appropriate region selection

=== Secrets Management

The project uses a layered secrets management approach:

[cols="1,2,2"]
|===
|Location |Purpose |Contents

|Azure Key Vault
|Production runtime secrets
|`MicrosoftAppId`, `MicrosoftAppPassword`, `AZURE-FUNCTIONS-BACKEND-URL`

|`.env` file
|Local configuration (non-secrets)
|`AZURE_KEY_VAULT_NAME`, `AZURE_RESOURCE_GROUP`, region settings

|GitHub Secrets
|CI/CD pipelines
|Azure credentials, subscription IDs (future)
|===

**Key Principles**:

* Bot credentials **never** stored in `.env` or `appsettings.json`
* Bot loads secrets from Key Vault at startup using managed identity
* Managed identity authenticates to Key Vault (no API keys needed)
* **Never commit secrets to Git**
* `.env` file excluded from source control (`.gitignore`)

=== Network Security

* NSG restricts inbound traffic to required ports only
* VM accessible via RDP (can be restricted to your IP)
* HTTPS required for all public endpoints
* Private networking optional for production

=== Access Control

* RBAC enforced on all Azure resources
* Key Vault access via managed identity
* Admin consent required for Graph API permissions
* Azure DevOps PAT with minimal scopes
